# Silly Bilibili

用于扫描、管理、播放和导出本地 B 站缓存视频的 Android 应用。

## 主要功能

- **缓存视频扫描与管理**：扫描本地 B 站缓存，显示标题、封面、时长、画质等信息；支持分类、条件筛选、模糊搜索、连续加载和长列表快速定位。
- **转换为 MP4**：将缓存中的 `video.m4s` 与 `audio.m4s` 无损重封装为标准 MP4，并显示后台转换进度。
- **视频播放**：可直接播放缓存或已导出的 MP4；支持选集、上一/下一条、倍速、全屏、后台播放与定时停止。全屏时上下轻滑约 12% 屏高即可跟手切换播放列表中的视频。
- **原视频状态查询**：查询缓存关联的线上视频状态，显示“在线”“已下架/不可访问”“暂无法核验”或“待核验”。

## 基本使用

1. 在 B 站中完成视频离线缓存。
2. 打开应用底部的 **扫描** 页面，完成目录访问配置后开始扫描。
3. 在首页查看已扫描视频：
   - 使用顶部搜索栏进行标题、UP 主等模糊搜索；
   - 点击过滤按钮按分类、画质、横竖屏、时长或大小筛选；
   - 长按视频卡片可分类或进行管理操作。
4. 点击视频卡片直接进入 **播放页面**：
   - 点击画面显示或隐藏控制栏；
   - 点击全屏按钮后，可上下滑动切换播放列表视频；
   - 在视频信息区使用 **选集**、**定时停止** 和 **转换为 MP4**；
   - 在设置中开启后台播放后，退出播放页可通过底部迷你播放器返回或关闭播放。
5. 在 **已导出** 页面查看、播放或删除已转换的 MP4。

### 原视频状态入口

- 单个视频：扫描视频卡片与播放页的信息区会显示状态。
- 全部刷新：进入 **设置**，使用“刷新所有视频状态”。

## Shizuku 配置（重要）

Android 11 及以上通常会隔离 `/Android/data/` 目录。应用会先尝试直接读取缓存目录；如果目录未隔离，**不需要配置 Shizuku**。如果扫描页提示目录已隔离，请按以下步骤配置。

1. 从 [Shizuku 官网](https://shizuku.rikka.app/download/) 或 [GitHub Releases](https://github.com/RikkaApps/Shizuku/releases) 安装 Shizuku。
2. 打开 Shizuku：Android 11+ 通常选择“无线调试启动”，按页面提示完成无线调试配对并启动服务。
3. 回到 Silly Bilibili，接受系统弹出的 Shizuku 授权请求。
4. 打开 **扫描** 页面，确认页面显示 Shizuku 已连接，然后开始扫描 B 站缓存。

常见问题：

- 重启手机后，Shizuku 服务可能需要重新启动。
- Android 11+ 的系统文件选择器通常无法授予 `Android/data` 权限；此时应使用 Shizuku。
- 如提示“目录不可读取”，先确认 B 站已缓存视频，再检查 Shizuku 是否仍在运行且本应用已获授权。

## 开发与版本控制

- 默认开发分支为 `dev`；开发改动提交后推送到 `origin/dev`。
- 每次影响功能或使用方式的改动，必须同步更新本 README。
- 本地 keystore 和 `keystore.properties` 已被 Git 忽略，不能提交。

```powershell
.\gradlew.bat testDebugUnitTest --no-daemon
.\gradlew.bat assembleRelease --no-daemon
```

生成的安装包位于：`app/build/outputs/apk/release/app-release.apk`。
