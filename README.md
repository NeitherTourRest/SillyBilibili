# Silly Bilibili

用于扫描、管理、播放和导出本地 B 站缓存视频的 Android 应用。

## 主要功能

- **缓存视频扫描与管理**：扫描本地 B 站缓存，显示标题、封面、时长、画质等信息；支持分类、条件筛选和模糊搜索。首页固定每页 40 个视频并预读下一页，滑到页尾自动换页，避免大量卡片长期堆积造成卡顿。返回首页或切换筛选时保留旧列表静默刷新，不闪加载圈；封面与线上状态每个视频每次进入应用后只核验一次，并用信号量限制并发，快速滚动时不会排队触发大量磁盘复制和网络请求。封面对缺失的缓存目录会自动发现真实封面文件（不局限于 cover.jpg，也识别 cover.webp、index.webp 等常见命名和任意图片文件）；完全没有封面文件的视频会直接取视频文件的第一帧生成预览封面（Shizuku 场景只复制 m4s 文件头几 MB 即可抽帧，失败才回退整文件复制），生成失败的视频会在几分钟后自动重试，不再一直停留在占位图。扫描页会逐步显示目录读取、元数据解析、文件核验、历史记录对账和保存进度；完整无筛选扫描会识别已被删除的缓存源文件，同时保留已导出的 MP4。重复扫描会合并更新缓存元数据，不会清除已生成的封面、分类、导出信息或线上状态。使用 Shizuku 时，目录元数据与文件核验会在常驻 UserService 内按批读取，避免为每批缓存额外创建 shell 进程。
- **转换为 MP4 与导出库**：将缓存中的 `video.m4s` 与 `audio.m4s` 无损重封装为标准 MP4，并显示后台转换进度。已导出的 MP4 可独立搜索、筛选（分类、缓存源状态、横竖屏）、排序、批量分类、重命名、播放和删除；应用回到前台或手动刷新时会核对文件管理器中的外部删改。
- **视频播放**：可直接播放缓存或已导出的 MP4；支持选集、上一/下一条、倍速、全屏、后台播放与定时停止。控制层采用无边框的常规浮层布局：顶部为返回、标题和集数，底部为时间、进度条和操作图标；点击画面即可显示或隐藏。全屏时上下轻滑约 7% 屏高即可跟手切换播放列表中的视频：拖动期间当前视频继续播放，相邻视频会预先解码并显示首帧；页面完全切换后才从该首帧开始播放，避免画面闪黑或闪回旧视频。Shizuku 直读缓存使用 256 KiB 预读块，减少跨进程随机读的次数。
- **原视频状态查询**：查询缓存关联的线上视频状态，显示“在线”“已下架/不可访问”“暂无法核验”或“待核验”。

## 基本使用

1. 在 B 站中完成视频离线缓存。
2. 打开应用底部的 **扫描** 页面，完成目录访问配置后开始扫描。
3. 在首页查看已扫描视频：
   - 使用顶部搜索栏进行标题、UP 主等模糊搜索；下滑到页尾会自动进入下一页；
   - 点击过滤按钮按分类、画质、横竖屏、时长或大小筛选；
   - 长按视频卡片可分类或进行管理操作。
4. 点击视频卡片直接进入 **播放页面**：
   - 点击画面显示或隐藏控制栏；
   - 点击全屏按钮后，可上下滑动切换播放列表视频；
   - 在视频信息区使用 **选集**、**定时停止** 和 **转换为 MP4**；
   - 在设置中开启后台播放后，退出播放页可通过底部迷你播放器返回或关闭播放。
5. 在 **已导出** 页面管理已转换的 MP4：
   - 搜索可匹配标题、UP 主、AV/CID 和导出文件名；
   - 横向分类标签可快速过滤，筛选按钮可按“缓存仍在/仅保留 MP4”、横竖屏和排序方式组合过滤；
   - 点“多选”可批量调整分类或删除；单个视频的更多菜单可编辑分类、重命名导出文件或删除；
   - 点刷新按钮可立即同步文件管理器里删除、替换或修改过的 MP4。

### 原视频状态入口

- 单个视频：扫描视频卡片与播放页的信息区会显示状态。
- 全部刷新：进入 **设置**，使用“刷新所有视频状态”。

## Shizuku 配置（重要）

Android 11 及以上通常会隔离 `/Android/data/` 目录。应用会先尝试直接读取缓存目录；如果目录未隔离，**不需要配置 Shizuku**。如果扫描页提示目录已隔离，请按以下步骤配置。

1. 从 [Shizuku 官网](https://shizuku.rikka.app/download/) 或 [GitHub Releases](https://github.com/RikkaApps/Shizuku/releases) 安装 Shizuku。
2. 打开 Shizuku：Android 11+ 通常选择“无线调试启动”，按页面提示完成无线调试配对并启动服务。
3. 回到 Silly Bilibili，接受系统弹出的 Shizuku 授权请求。
4. 打开 **扫描** 页面，确认页面显示 Shizuku 已连接，然后开始扫描 B 站缓存。

常见问题：

- 重启手机后，Shizuku 服务可能需要重新启动。
- Android 11+ 的系统文件选择器通常无法授予 `Android/data` 权限；此时应使用 Shizuku。
- 如提示“目录不可读取”，先确认 B 站已缓存视频，再检查 Shizuku 是否仍在运行且本应用已获授权。

## 开发与版本控制

- 默认开发分支为 `dev`；开发改动提交后推送到 `origin/dev`。
- 每次影响功能或使用方式的改动，必须同步更新本 README。
- 本地 keystore 和 `keystore.properties` 已被 Git 忽略，不能提交。

```powershell
.\gradlew.bat testDebugUnitTest --no-daemon
.\gradlew.bat assembleRelease --no-daemon
```

生成的安装包位于：`app/build/outputs/apk/release/app-release.apk`。
